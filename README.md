# 热点营销工作台 · 电商媒体营销 Demo

一个面向「电商 × 媒体热点」的营销工作台 Web 原型：覆盖 **抓热点 → 建议匹配 → 手动匹配 → 创作文案 → 审核发送** 的全流程闭环演示。

> 本项目实现了 **Web 工作台 + 运营后台** 两大部分。AI 能力（商品匹配、文案生成）由外部 **Coze 工作流** 或 **大语言模型（LLM）** 提供；新闻抓取改为 **可配置的新闻源**（内置平台热榜 + 运营自定义订阅源），不再强依赖 Coze。前端负责：调用后端 API → 接收/解析 JSON → 渲染页面 → 保持 5 步数据状态贯通。

---

## 技术栈

| 部分 | 技术 |
| --- | --- |
| 工作台（前端） | React 19 + TypeScript + Vite 8 + Tailwind CSS v4 + lucide-react |
| 运营后台（admin） | 纯静态 vanilla HTML/CSS/JS（classic script，**零依赖**，可 `file://` 双击打开） |
| 开发服务器 | Vite 8（自带 dev server + 中间件转发，无需额外后端进程） |
| 品牌色 | 紫色 `#7c3aed`（工作台与后台共用，可在后台统一修改） |

**环境要求**：Node.js ≥ 20.19 或 ≥ 22.12（Vite 8 要求）。

## 快速开始

```bash
npm install      # 首次安装依赖（已安装可跳过）
npm run dev      # 启动开发服务器
```

启动后：

- 工作台：http://localhost:5173/
- 运营后台：http://localhost:5173/admin/index.html （页面内用 hash 路由，例如 `#/news`）

> 说明：Vite 8 不支持通过 `--root` 命令参数指定根目录，请在项目根目录执行 `npm run dev`；如需显式启动也可用 `node node_modules/vite/bin/vite.js`。

## 整体架构

```
┌──────────────┐         ┌──────────────────────────────┐         ┌────────────────────┐
│  工作台 (React) │ ──────▶ │  Vite 中间件（vite.config.ts）  │ ──────▶ │ Coze 工作流 / LLM    │
│  :5173/        │ ◀────── │  /api/coze /api/llm /api/news │ ◀────── │ 外部 AI 能力          │
└──────────────┘         │  /api/admin-config /api/coze-trial │    └────────────────────┘
                         │  /api/news-test               │
┌──────────────┐         └──────────────────────────────┘
│  运营后台 (admin) │ ──────▶ 同一组 /api/admin-config 读写 server-config.json
│  :5173/admin  │
└──────────────┘
```

- **工作台** 与 **后台** 共享同一套配置（服务端权威的 `admin/server-config.json`）。
- Vite 在开发期充当「后端」：`vite.config.ts` 中注册了 6 个 API 中间件，负责转发 Coze/LLM 请求、托管新闻抓取、并提供配置读写接口。Token / API Key 只在服务端注入，不进入前端打包产物，避免暴露与跨域问题。
- 改动 `vite.config.ts` 后**必须重启 dev server** 才生效。

### 三级配置体系

所有可运营的配置（商品库、文案模板、匹配方式、新闻来源、品牌色等）按「三级」读取：

| 层级 | 来源 | 优先级 |
| --- | --- | --- |
| 本机浏览器 | `localStorage`（`hg_admin_config_v1`） | 最高（离线镜像） |
| 服务端 | `admin/server-config.json`（经 `/api/admin-config`） | 中 |
| 内置默认 | 代码常量（`BUILTIN_DEFAULTS` / `ADMIN_DEFAULTS` / `BUILTIN_*`） | 兜底 |

- 后台「保存」会同时写服务端并镜像到本机；顶栏徽章标明当前实际生效来源：**紫=服务端 / 琥珀=本机 / 灰=内置默认**。
- 直接 `file://` 双击打开后台时只能读到内置默认 + 本机镜像。

## 工作台（5 步流程）

顶部导航栏含 Logo / 站点名、通知、**「重置进度」按钮**（清空 sessionStorage 持久化的工作台状态，回到初始；仅关闭标签页才自动清，刷新不清，故提供按钮）、运营后台入口、用户（运营小王）。

左侧流程导航 5 步，已完成步骤以绿色对勾标记；右侧工作区随选中 Step 动态渲染，数据在 5 步间保持连贯。

| Step | 名称 | 说明 |
| --- | --- | --- |
| 1 | **抓热点** | 实时抓取「已启用来源」的热点（按热度排序），每条带**风险等级标签**（红=禁止借势 / 琥珀=需人工判断 / 绿=可借势），挑选要借势的爆款热点。 |
| 2 | **建议匹配商品** | 系统按关键词自动推荐匹配度最高的商品，可「采纳」。 |
| 3 | **匹配商品** | 从商品库手动搜索 / 筛选 / 多选自绑定，可搜可选。 |
| 4 | **创作文案** | 按「创作风格」（`creativeStyles`）逐个跑一遍文案生成，产出多个**候选版本**以风格名做 tab，支持复制 / 选用。 |
| 5 | **审核并发送** | 微博卡片预览、合规审核标记、一键发送（模拟）。 |

**状态贯通**：Step1 选中的新闻 → Step2/3 的匹配上下文 → Step4 的 `user_prompt` → Step5 预览，全程由 `WorkflowContext`（reducer + sessionStorage 持久化 `hg_workflow_state_v1`）保持。

## 重点功能详解

### 1. 可配置新闻源（替代原 Coze getNews 工作流）

工作台 Step1 不再依赖单一 Coze 工作流，改为调用 `/api/news`（服务端聚合**所有「已启用」来源**，按热度排序）。

**来源管理（后台 `#/news`）**
- **内置平台热榜（5 个，不可删）**：微博热搜 / 今日头条热榜 / B站热门 / 知乎热榜 / 百度热点。
- **运营自定义订阅源（可增删）**：支持类型 `rss` / `json` / `weibo` / `toutiao` / `bilibili` / `zhihu` / `baidu`。
  - 添加时校验地址格式（`^https?://` + `new URL()` 解析）；`kind=json` 需填写字段路径 `jsonTitlePath` / `jsonUrlPath` / `jsonBriefPath`。
  - 每个来源可**启用 / 停用**；自定义来源可**删除**。
- **「⚡测试全部来源」按钮**：真实发起一次抓取（`POST /api/news-test`，8s 超时），逐源显示：成功/失败、抓到条数、耗时(ms)、失败原因（超时 / 地址错误 / DNS / 401 / 403 / 返回内容不是有效订阅源等）。
- **合规提示**：公开热榜 API 仅用于原型演示；正式上线应改用官方开放平台或商业舆情服务，并遵守 `robots.txt` 与服务条款。
- **风险识别规则**：按关键词预判借势风险，分为「禁止借势」与「需人工判断」两类（前端 `classifyRisk` 与服务端规则镜像一致）。

**样例订阅源**（后台加源时可直接填这两个地址试效果）：
- RSS：`http://localhost:5173/sample-news.rss.xml`
- JSON：`http://localhost:5173/sample-news.json`

> 已知限制：内置的微博/知乎在沙箱环境会因反爬返回 403/401，百度在原型环境返回 HTML 渲染页——均被归为「失败」并给出清晰原因，属预期行为，并非 bug；生产接入官方开放平台即可稳定。

### 2. 商品库管理（`#/products`）

- **可视化维护**：统计（总数 / 品类数 / 价格区间 / 均价）、卡片/表格视图切换、搜索 / 筛选 / 排序；每个商品有 emoji 图标 + 渐变背景头（默认 🛍️）。
- **新增 / 编辑弹窗**：左侧表单 + 右侧实时预览卡片。
  - 字段：编号自动生成不重复、名称必填、图标（31 个 emoji 快捷面板 + 手动）、渐变（12 套预设）、售价/原价（>0 且原价≥售价，否则拦保存）、品类（选已有或输入新）、卖点标签（Enter 添加 / ✕ 删除，建议 2~4 个）。
  - 校验错误精确到字段（非通用弹窗）。
- **多选 + 批量操作**：
  - **批量删除**：二次确认弹窗会列出每件商品被哪些热点推荐引用（如「该商品被 N 条热点推荐引用，删除后这些推荐会失效」），让运营知情后再决定；完成后反馈「成功 X 件」。
  - **批量改品类**：勾选后一键改品类，列表与统计同步更新；完成后反馈成功/跳过数量及原因。
- **导入 / 导出（双格式）**：
  - 导出 **JSON**（结构化，适合备份/迁移）或 **CSV**（表格，适合表格软件批量编辑）。表头含中文，编号用于稳定匹配，保证「导出→再导入」完全一致。
  - 导入 **JSON 或 CSV**：先弹「导入预览与校验」窗，显示解析结果与问题（如某行价格为负），确认后才写入，避免脏数据污染商品库。

保存后工作台即时生效（新增商品可在 Step2 兜底匹配、Step3 搜索选用）。

### 3. 商品匹配双模式（`#/match`）

`matchGoods` 支持两种匹配方式（由 `MatchConfig` 驱动）：

- **Coze 模式**：走原 Coze 工作流（输出 `output_goods_list`）。
- **LLM 模式**：分析新闻 → 生成匹配关键词 → 在商品库检索推荐命中商品。配置含 `baseURL` / `model` / `apiKey` / `simulate`（无 key 或勾选 simulate 时本机模拟），并可在页面「试运行」（填 title/brief 调 `/api/llm`，解析关键词渲染）。

### 4. 文案模板与多候选（`#/prompts`）

- 模板分三块：系统角色设定（`system`）、素材模板（`template`）、单件格式（`itemFormat`）；占位符在运行时替换，不认识则原样保留。
- **创作风格 `creativeStyles`**：可增删改、上下移（删到 0 被拦），每个风格独立跑一次文案生成 → Step4 以风格名做 tab 产出多候选。
- **语调预设 `tonePresets`**：可维护。
- 支持实时预览 + 试运行（无 key / 勾选 simulate 则本地模拟，否则真调 `/api/llm`）。

### 5. 风险控制

- 工作台 Step1 每条热点旁显示**风险等级 pill**：红=禁止借势、琥珀=需人工判断、绿=可借势；悬停有说明。
- 规则与后台「风险识别规则」说明、服务端风控保持一致，最终以人工审核为准。

### 6. 文案效果评测体系（第 6 步 · 文案评测台）

一套**与 UI 解耦**的评测引擎（`src/eval/*`，纯 TS，可被评测台与 Step4「一键修正」共用），用于量化文案质量、自动返工、并用评测结果反推提示词优化。

- **机器校验（硬规则）**：对每个「文案 + 素材」跑 8 项检查并加权计分——字数区间、素材指定话题标签、emoji 数量、广告法违禁词（硬伤，最高权重）、编造价格（硬伤）、结尾互动引导、残留排版符号、是否提到商品。违禁词与编造价格命中即**硬伤**，其余为**瑕疵**，返工处理方式不同。
- **模型评审（可选）**：独立一次低温度 LLM 调用，对 4 个维度各打 1–5 分（热点关联度 / 素材还原度 / 传播吸引力 / 语气自然度）+ 一句点评；解析做了容错（剥离代码块、截取首个 `{` 到最后一个 `}`），解析失败不影响本轮。
- **总分**：机器分与模型分按权重合并（默认 50/50，可配）；关闭评审则只用机器分。
- **自动返工（核心，工作台 Step4 也用）**：校验不过时，把「可修复问题清单」（字数 / 违禁词 / 编造价格 / 标签 / 互动 / 残留符号，不含「未提到商品」这种改了也白改的）交给模型改写并重新校验；**只接受分数提升的版本**，没提升就保留上一版（防回归）；全程可追溯（轮次、修了哪些、还剩哪些）。离线 / 无密钥环境下由 `simulateRewriter` 兜底跑通机制。
- **评测台界面（3 个视图）**：
  1. **用例管理**：用例 = 素材 + 语调，支持增删改查、选入本轮、从真实业务数据（热点 + 商品库）一键播种。
  2. **跑评测**：配置风格 / 并发 / 重复次数 / 是否评审 / 权重 / 参考单价 / 模型；跑前预估任务数与费用；支持中途停止；实时进度条 + 明细表；汇总看板（机过率 / 模型均分 / 违禁命中 / 编造数 / 总费用 / 总耗时 / 预估费用）；明细行可展开看完整文案、逐检查项、4 维评审分 + 点评、人工 👍👎 + 备注；分数绿/橙/红分级。
  3. **历史与对比**：保存提示词快照 + 短标签作为 A/B 锚点；选 2 次运行看指标差异（带箭头与颜色）、逐用例对比、高亮变差用例、展示提示词 diff。
- **用评测结果改提示词**：评测台与后台「评测」页都开放评审提示词 / 返工提示词 / 违禁词 / 权重等配置；根据失败画像（如字数超限→把字数写成硬要求、编造价格→写成死约束、格式不稳→补合规示例）反推并保存新提示词，再跑一轮 A/B 验证。

> 实测：用 `npm run eval:harness` 可离线跑通「构造违规文案 → 机器校验全抓 → 1 轮返工清零 → A/B 对比」全流程并输出真实数字（模型评审在无密钥环境下走 `simulateReview` 兜底，标注 [SIM]）。

## AI 能力接入

### Coze 工作流（已发布，拆分为 3 个独立工作流）

> 早期单一工作流 `<COZE_WORKFLOW_ID_ABANDONED>` 已废弃，拆分为以下三个：

| 工作流 | ID | 入参 → 出参 |
| --- | --- | --- |
| getNews（热点抓取） | `<COZE_WORKFLOW_ID_GETNEWS>` | `(input, count) → news_list` ⚠️ 现已非主路径，被可配置新闻源取代 |
| matchGoods（商品匹配） | `<COZE_WORKFLOW_ID_MATCHGOODS>` | `(news{title,brief,url}) → output_goods_list: Array<{documentId,output}>` |
| createCopy（文案生成） | `<COZE_WORKFLOW_ID_CREATECOPY>` | `(news, products:{product,price,classification,month,detail}[], user_prompt) → output_wb` |

- 前端经同源 `POST /api/coze` 转发至 `https://api.coze.cn/v1/workflow/run`，服务端注入 `Authorization`。
- `createCopy` 节点「系统提示词留空、用户提示词」按后台模板下发；前端兼容 `output_wb / output_red_list / copies / output / text` 多字段名与数组/字符串。
- **离线兜底**：Coze 调用失败 / 网络不可用时自动回退本地模拟文案，页面标注「模拟数据」，保证 Demo 永远可用。

### LLM 大模型模式

- 通过 `/api/llm` 中继（自动剥离 `baseURL` 末尾 `/` 与 `/chat/completions` 避免双拼），兼容 OpenAI 风格接口（如 Coze OpenAI 端点 `https://api.coze.cn/api/v1/chat/completions`）。
- 用于「商品匹配（LLM 模式）」与「文案模板试运行」。

### Vite 中间件端点（`vite.config.ts`）

| 端点 | 作用 |
| --- | --- |
| `/api/coze` | 转发 Coze 工作流调用（注入鉴权） |
| `/api/llm` | 转发 LLM（OpenAI 风格）调用 |
| `/api/admin-config` | 读写 `server-config.json`（GET 读 / POST 写，写前备份 + 校验） |
| `/api/coze-trial` | Coze 试运行 |
| `/api/news` | 聚合所有「已启用」新闻来源，按热度排序返回 |
| `/api/news-test` | 逐源真实抓取诊断（成功/失败/条数/耗时/原因） |

## 功能边界与已知限制

- ✅ 调用外部 AI 能力、解析其 JSON、渲染页面、5 步状态贯通、商品库可视化运营、新闻源可配置与测试。
- ❌ 不实现新闻爬虫算法 / 商品推荐算法 / LLM 推理本身（均由 Coze 或外部 LLM 完成）。
- ❌ 微博「发送」为模拟动作，仅前端状态演示。
- ⚠️ 内置平台热榜（微博/知乎等）在原型/沙箱环境常因反爬返回 401/403，属预期；生产应接入官方开放平台或商业舆情服务。
- ⚠️ `vite.config.ts` 改动需重启 dev server；令牌/密钥仅保留在服务端，写入服务端前会剥离明文 `apiKey`。

## 常见问题

- **后台改了配置，工作台没变？** 配置为服务端权威，保存成功后刷新工作台（建议 `Ctrl+Shift+R` 硬刷新）即可生效；若后台是以 `file://` 打开，则只影响本机镜像。
- **`/api/news` 抓不到某来源？** 到后台「新闻来源 → 测试全部来源」看逐源诊断；确认该来源已启用且地址正确（自定义源注意 `kind` 与字段路径）。
- **想清空工作台进度？** 点顶栏「重置进度」按钮，或 `F12` 控制台执行 `sessionStorage.clear()` 后刷新。
- **端口被占用？** 释放 5173 端口后重试；或显式用 `node node_modules/vite/bin/vite.js --host` 启动。
